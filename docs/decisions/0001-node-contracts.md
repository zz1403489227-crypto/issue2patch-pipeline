# 0001 节点的输入输出契约

日期：2026-11-15 · 阶段 0

## 决定

八个节点之间只传 `src/issue2patch/contracts.py` 里声明的字段，每个节点的输入在运行时原样存成 `input.json`（单节点重测就靠它）。

| 节点 | 读哪些上游字段 | 产出 |
|---|---|---|
| 1 准备环境 | TaskSpec（仓库、基线提交、issue 文本、镜像） | SandboxInfo：容器、镜像 ID、HEAD |
| 2 上下文预取 | TaskSpec | 候选源文件、候选测试文件、抽到的符号和路径 |
| 3 复现 | issue、候选文件、仓库的测试运行方式 | 测试文件路径、运行命令；确定性检查：在原代码上是否失败 |
| 4 实现 | issue、候选文件、可用的复现测试（路径、命令、失败输出） | 改动的文件列表、改动说明 |
| 5 校验 | 复现测试、改动的文件 | 每项检查的通过与否、摘要、日志路径 |
| 6 修复 | 没通过的检查（摘要加日志路径）、当前 diff | 轮数、最终校验结果 |
| 7 评审 | issue、最终 diff（看不到实现节点的对话） | approve / request_changes、越界文件、理由 |
| 8 出补丁 | 复现测试路径（用来排除） | 补丁文件、包含和排除的文件、能否干净地打到基线上 |

## 规则

- 隐藏测试、参考补丁、`hints_text` 不进任何契约。`tasks.to_task()` 只取公开字段；构造测试解析器时用 `tasks.sanitized()` 把这些字段清空。
- Agent 节点的结构化输出走一个 `submit` 工具（参数有 schema），不从自由文本里解析。
- 节点契约由确定性代码兜底：复现节点只许新增测试文件，其他改动一律回滚并记录；实现节点改了复现测试会被恢复；评审节点改了任何文件都会被整体还原。
- 最终补丁只包含源码改动：复现测试、测试目录下的文件、未跟踪的非 Python 文件（构建和测试的副产物）都排除。

## 为什么

- 节点之间只传契约字段，是上下文管理的第一道闸：实现节点看不到复现节点的完整对话，评审节点看不到实现节点的推理，各自的上下文不会互相污染。
- 用 submit 工具拿结构化输出，格式错误能被工具参数校验当场拦住并回给模型，而不是事后解析失败。
