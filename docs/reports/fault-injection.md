## 第 9 项为什么需要专门处理

最初的实现里，数据库连接失败会直接抛异常：worker 判定为基础设施错误，把消息退回队列；同一个 worker 立刻又拿到它，再失败……几秒内就会用光队列的 3 次投递上限，任务进死信队列。现在 `state_pg.connect()` 会在 3 分钟内带退避地重连，短暂的数据库重启对任务是透明的；更长的故障仍然按基础设施错误处理。

## 第 5 项的含义

“格式错误的工具调用”不一定会以错误的形式出现。Pi 为了支持流式输出，用部分 JSON 解析器读工具参数，截断的 JSON 会被补全后执行。对 `bash` 这类工具，补全后的命令和模型原意大概率一致；但对 `edit` 这类参数里有长文本的工具，补全可能产生不完整的替换内容。目前没有观察到实际问题，记在这里，作为将来排查 edit 异常时的线索。
